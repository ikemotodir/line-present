# Webページ全画面スクショの Chrome 拡張機能 ― Claude Code への丸投げ指示書

## あなた（Claude Code）へ
私はプログラムが分かりません。このファイルの手順どおりに、Chrome の拡張機能「今見ているWebページを、一番下まで丸ごとPNGとPDFにする道具」を作り、自分で試してから渡してください。
- 自分で使うための拡張機能として作ります（Chrome ウェブストアには出しません）。
- 途中で私に質問しないでください。迷ったら良いと思う方を選び、最後に理由を1行で書いてください。
- 管理者のパスワードが要る方法は使わないでください（私が入力する手間になるため）。
- フォルダは分ける：拡張機能の本体は `extension`、テスト用は `tests`。Windows でも Mac でも、`extension` フォルダを Chrome に読み込めば使えるようにします。

## 1. 作るもの（これで完成）
- Chrome 拡張機能（Manifest V3）。いつもの Chrome で、今見ているページのまま使える（ログインし直さない・別の画面を開かない）。
- 権限は `debugger`・`downloads`・`offscreen`・`scripting`（`scripting` を使うには `host_permissions` に `<all_urls>` も要る）。ページに出すボタンはコンテンツスクリプト（`<all_urls>`）。ショートカットは `commands`。
- 数字は決めておく（誰が作っても同じになるように）：日時は `YYYYMMDD-HHMMSS`、題名は50文字まで、PNG は1辺30,000画素・面積5,000万画素まで、PDF は1ページ14,000pt まで、余白の判定は横一列の各色の差が6以内。
- 画面の右下に小さなボタンを出す（Shadow DOM で作り、ページの見た目を壊さない）。押すと、ページの一番下まで PNG と PDF にして保存する。
- 保存は `chrome.downloads` の `filename` を `PATTI_SHOT/日時_題名.png` の形で。題名から、ファイル名に使えない文字（: ? / * " < > | など）と、末尾の点・空白を取り除き、長さも切る。保存先は Chrome で設定したダウンロード先の中になる。
- 撮った画像はどこにも送らない。PDF を作る部品を使うなら、ネットから読み込まずに拡張機能の中に入れる。
- 画像をつなぐ処理と PDF 化は、裏方（service worker）ではなく **offscreen 文書**（理由は BLOBS）で行い、できたファイルは Blob URL で `chrome.downloads` に渡す（大きな画像を data URL で渡さない）。

## 2. 撮り方（ここがいちばん大事）
- 撮影は `chrome.debugger` を使い、`Page.captureScreenshot` で撮る。接続してから画面の高さを測る（接続すると画面上部に黄色いバーが出るため）。途中で接続が切れたら中止して知らせる。
- **CSSの高さ×画面の倍率（devicePixelRatio）がおよそ16,000を超えないなら**、`captureBeyondViewport` で1回で撮る。それを超えると画像の中身が静かに壊れることがあるので、スクロールしながら撮ってつなぐ。
- 1回で撮るときも、撮る前に一度下まで流して読み込ませてから上に戻る（遅れて読み込まれる画像が空白にならないように）。
- スクロールしながら撮るときは：
  - 画像の中身を照らし合わせて位置を探す方法は使わない（ほぼ同じ行が並ぶ表では別の行に合ってしまう）。**撮ったときのスクロール位置に、そのまま置く**。撮り残した場所は、その位置を狙って撮り直す。
  - スクロールは瞬間移動にする（なめらかスクロールを止める）。動かすたびに、見えている画像の読み込み完了と、2フレーム分の描画を待ってから撮る。
  - 上に貼りつくヘッダー、途中から出てくる浮いたボタン、**自分が出した右下のボタン**は、撮影中は隠す。ただし、いちばん上の1枚目だけはヘッダーを残す（どこにも写らないと困るため）。途中から出てくる物はスクロールの後に出るので、スクロールして1フレーム待ってから隠す（先に隠すと写り込む）。
  - ページ全体が動かず、中の枠だけがスクロールするサイトもある。window が動かないときは、いちばん大きくスクロールする要素を探し、その要素を動かして撮る（撮るのは枠の中だけ。周りの見出しは入れない）。
- 下までスクロールしてから遅れて表示されるページがある。**撮り終わったら、もう一度ページの長さを測り（最長1.5秒待つ）、伸びていたら撮り足す**。伸びたときは、元の末尾（下に押されたフッター等）も撮り直す（古いまま残って行が欠けるため）。終わらないページ（無限スクロール）は、上から10万px で止めて「途中まで」と知らせる。
- 画面の拡大率（100%・125%・200% など）で倍率がずれないように、実際に返ってきた画像の幅を測って補正する。丸め誤差（0.5%以内）なら `devicePixelRatio` を使う。枠の切り抜きは画素ぴったりの大きさにする（125% で半端な行が白い線になり、番号が重複した）。
- 1枚の画像の大きさにはブラウザの上限がある（1辺およそ32,000画素）。だから1で決めた 30,000画素・5,000万画素を超えるときは、PNG を `_001`・`_002` の連番に分けて保存し、PDF には全部入れる。
- PDF の1ページの高さは、1で決めた 14,000pt まで（PDF の仕様上の上限 14,400pt の手前）にする。区切りは、上限の手前で横一列がほぼ同じ色の行（余白）を探して切る。見つからなければ上限で切る。
- 途中までしか撮れなかったときは、黙って保存せず、画面ではっきり知らせる。撮れないページ（chrome:// やウェブストア）では、理由を画面に出す。

## 3. 合格の条件（満たすまで「完成」と言わない）
- 練習用のページを自分で作り、`localhost` の簡易サーバーで配る（file:// では開かない）。
  1. 1行ずつ番号を入れた、画像の上限を超えるほど長いページ
  2. ほぼ同じ行がずらっと並ぶ表のページ
  3. スクロールすると、遅れて行が増えていくページ
  4. ページ全体は動かず、中の枠だけがスクロールするページ
- 撮った画像から番号を読み取り（色で番号を埋め込むなど）、**番号が1回ずつ・順番どおり・抜けなし**かを機械で数える。見た目や「空白がないか」では判定しない。
- 画面の倍率を変えても同じ結果になるか試す（`--force-device-scale-factor=2` で倍率2も再現する）。
- 自動テストは、Chrome for Testing（または Chromium）に Puppeteer で拡張機能を読み込んで行う（ふつうの Chrome は自動テストで拡張機能を読み込めないため）。Node が無ければ、管理者のパスワードが要らない方法で入れる（私が入力する手間になるため）。Puppeteer 25 なら `enableExtensions: ['フォルダ']` で読み込め、画面を出さない headless でも動く。ダウンロード先は、ユーザーデータの `Default/Preferences` に先に書いて固定する。
- 本物の Mac で試していなければ、報告に「Mac は未確認」と書く。画面でしか確かめられない所（ふつうの Chrome への読み込み・黄色いバー・ショートカットの実際のキー・ツールバーのアイコン）も「未確認」と書く。試していないことを「できました」と言わない。

## 4. 私が入れる手順（Windows も Mac も同じ）
- 説明書（README）に1手ずつ書く。
  1. Chrome のアドレス欄に `chrome://extensions` と入れて開く
  2. 右上の「デベロッパー モード」をオンにする
  3. 「パッケージ化されていない拡張機能を読み込む」を押して、`extension` フォルダを選ぶ
  4. 入れる前から開いていたページは、一度再読み込みする
- あわせて書くこと：フォルダはあとで動かさない／撮影中に黄色いバーが出るのは正常／ショートカットがほかとぶつかったら `chrome://extensions/shortcuts` で変える。

## 5. 途中で止まっても続きから
- 終わった手順・残っている手順・つまずいた所を、作業フォルダの `進み具合.md` に書きながら進める。
- 私が「続きから」と送ったら、`進み具合.md` を読んで止まった所から再開する。最初からやり直さない。
