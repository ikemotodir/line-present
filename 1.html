【まずこれやれ①】AIの「メモリ」に焼きこむ「絶対ルール」10選

ボクのAIには、毎回かならず守ってもらう「絶対ルール」が18個入っています。
この特典は、その中から誰でもそのまま使える10個を選んで、やさしく言い直したものです。

  • コピーして、AIの設定に貼るだけで使えます
  • ChatGPT でも Claude でも使えます
  • ボクはAIでアプリやホームページを作っているので、例はその話が多めです。ルールの文は、調べものや文章づくりにも使えるように言い直してあります

まず「メモリ」ってなに？

AIは、新しいチャットを始めると、前に伝えたことを覚えていないことがあります。
だから「専門用語は使わないで」「短く答えて」と、毎回言い直すことになりがちです。

そこで、AIが毎回読んでくれる「決まりごと」を書いておける場所があります。
この特典では、それをまとめて「メモリ」と呼んでいます。

じつは、書く場所は2種類あります。

AIが自分で覚えるほう自分で書いておくほう
書く人AIあなた
向いているもの好みや、前に話したこと毎回守ってほしいルール

絶対ルールは「自分で書いておくほう」に入れます。
AIが自分で覚えるほうは、何を残すかをAIが判断するので、全部が残るとは限らないからです。

どこに入れる？（使っているAI別）

ChatGPT

  • パソコン：「設定」→「パーソナライズ」→「カスタム指示」の欄に貼る
  • スマホのアプリ：「設定」→「ChatGPT をカスタマイズ」→「カスタム指示」の欄に貼る
  • どちらも「カスタマイズを有効にする」がオンになっているか確認します
  • 無料版は1,500文字まで入ります。いちばん下の「まとめてコピー用」は、この中に収まる長さにしてあります
  • AIが自分で覚えたことは「設定」→「パーソナライズ」→「メモリ」で見られます

Claude（チャット）

  • 全部のチャットに効かせる：左下のイニシャル →「設定」→「Claudeの指示」に書く
  • 1つの仕事だけに効かせる：プロジェクトを開いて「プロジェクト指示を設定」→ 貼って「指示を保存」
  • AIが自分で覚えたことは「設定」→「メモリ」で見られ、直したり消したりできます。チャットで「これを覚えておいて」と頼むこともできます

Claude Code（パソコンの作業まで任せられる、開発用のAI）

  • 「CLAUDE.md」というメモのファイルに書きます。Claude Code は作業を始めるたびに、これを読みます
  • いちばん楽なのは、Claude Code に「このルールを CLAUDE.md に追加して」と頼むことです
  • 絶対ルールは、どの作業でも読んでほしいもの。なので「どのフォルダの作業でも読まれる、ユーザー用の CLAUDE.md に追加して」と頼むのがおすすめです（フォルダごとの CLAUDE.md に入れると、そのフォルダの作業にしか効きません）
  • 自分で開くなら、/memory と打つと一覧が出て、選ぶと開けます（まだ無いファイルは、選ぶと作られます）
  • 公式のおすすめは、1つのファイルにつき200行以下です

画面の名前は、アップデートで変わることがあります。見つからないときは、設定の中の「パーソナライズ」や「指示」のあたりを探してください。

ChatGPT のヘルプの日本語ページは機械翻訳なので、画面の言葉と少し違うこともあります。

絶対ルール10選

1つずつ「コピーして使う文」「なぜ要る？（ボクの実例）」「ひとこと」の順に並べています。
文の中の「私」は、自分の呼び方に変えてもOKです。

1. 私の手を動かさせない

私の手作業を増やさない。あなたにできる部分は全部やってから渡す。私に頼む手順が残るなら、減らせないか先に考える。

なぜ要る？
ボクがAIでアプリを作ったとき、最初は更新のたびに自分の手でやっていました。「これ手動じゃ無くできないかな。毎回めんどくさいんだけど…」と言ったら、AIが全自動で更新する仕組みに作り直してくれました。

ひとこと
AIを使う目的は、自分にしかできないことに時間を使うこと。言わないと、AIはふつうに「〇〇してください」と作業を頼んできます。

2. 人に頼む前に、本当に人にしかできないか確かめさせる

「これはあなたがやって」と言う前に、本当に人にしかできないか確かめる。人にしかできない作業は最初にまとめて伝え、なぜ自動でできないかも添える。

なぜ要る？
ボクの場合、「本人にしかできない1手」を待って止まっていた作業が、同時に5件ありました。中には、ボクが3分で済む作業をするまで、何週間も止まっていたものもあります。

ひとこと
パスワードの入力や支払いは、本当に人がやる作業です。それが最初に分かれば、先に片づけておけます。

3. 途中で止まらず、最後にまとめて聞かせる

確認のために途中で止まらない。任せてよい部分は最後までやり切り、聞きたいことは最後にまとめて聞く。ただし公開・送信・お金が動くことは、やる前に必ず確認する。

なぜ要る？
ボクのAIは、夜ボクが寝ている間に、20体くらいで手分けしてお願いごとを進めています。途中で「これでいいですか？」と返事を待たれたら、朝まで何も進みません。

ひとこと
「公開・送信・お金」だけは先に確認、という例外まで書いておくのがポイント。そこは人が決めるところです。

4. 出す前に、目で見て確かめさせる

作った物は、出す前に自分で見直す。動くかだけでなく、見た目・誤字・文字化け・改行のズレまで確かめる。確かめていないのに「できました」と言わない。

なぜ要る？
「できました」と渡されたページを開いたら、クリックもズームも動かなかったことがあります。思わず「ボクはテスターじゃないと何度も言ってるでしょう！」と言いました。

ひとこと
AIは、自分が作った物を実際に開いて見られないことがあります。そのときは「ここは確かめていません」と正直に書いてもらうのが大事です。

5. 「本当にそれだけ？」を疑わせる

直したら「本当にそれだけか」を疑い、別の角度からもう一度点検する。同じ問題が他の場所に残っていないか、全体を見直す。

なぜ要る？
ボクが作った道具で、AIが「直しました」と言うたびに、同じ不具合がまた出たり、別の不具合が出たりして、5日間で6回以上くり返しました。

ひとこと
「直しました」だけで終わらせず、どこを点検したかも書いてもらうと安心です。

6. 根拠を示させる

事実や数字には、出どころ（URLと確認した日）を付ける。確かめられないことは「未確認」、推測は「推測」と書き分ける。

なぜ要る？
AIに市場を調べてもらったら、ライバルが弱くて勝てそうだという高い点数が出ました。それを信じて準備を始めたら、あとで同じ分野に、利用者が1,000万人を超える大きな道具があると分かって、やめました。

ひとこと
AIの答えを人に話すなら、なおさらです。出どころのない話を渡すと、自分の信用が落ちます。

7. ボタンの名前を想像で書かせない

操作の手順では、ボタンやメニューの名前を記憶や想像で書かない。確かめられないときは「右上の点が3つ並んだボタン」のように、場所と形で伝える。

なぜ要る？
あるお金の受け取りサービスの設定手順を書いてもらったら、AIが画面の言葉を3回続けてまちがえました。ボタンやメニューの名前が少しずつ違う、というまちがいです。公式の説明書どおりに書いたのに、実際の画面とは言葉が違っていたこともありました。こういう小さな違いが、いちばん人を不安にさせます。

ひとこと
画面はアップデートで変わります。手順を聞くときは、いまの画面のスクリーンショットを見せてから聞くのがおすすめです。

8. 報告と質問を、短く分かりやすくさせる

報告は「原因をひとこと→やったこと→これからどうするか」の3つで短く。質問は専門用語を使わず、そこだけ読めば答えられるように書く。

なぜ要る？
AIから「HTTPSスキャン」について判断を求められて、何を言っているのかさっぱり分からなかったことがあります。

ひとこと
ボクはAIの作業の途中は見ていません。最後の報告と質問だけを読みます。忙しい人ほど効くルールです。

9. 間違っていたら、はっきり言わせる

私の案や頼み方がベストでないと思ったら、黙って従わずに先に言う。間違っていれば、理由をつけてはっきり否定する。

なぜ要る？
確認のために動画を作ってもらったら、時間もAIの使用量もかなり使いました。実は、実物を開けば済む話でした。そのとき「動画共有がベストじゃないなら『やめた方が良い』って言ってよね」と伝えました。

ひとこと
ボクが有料プランを Claude に決めたのも、「それは違う。やめた方がいい」と否定してくれたのがきっかけでした。

10. 頼んでいない物を作らせない

頼まれていない物を「あると良さそう」で先に作らない。作る前に、本当に今必要かを、実際の画面や公式の情報で確かめる。

なぜ要る？
AIが「これも必要なはず」と思い込んで、頼んでいないページを作ったことがあります。あとで実際の画面を見たら、必須ではありませんでした。10分見れば分かることを想像で作って、時間と使用量を使いました。

ひとこと
要らない物を作った時間とAIの使用量は、そのまま無駄になります。「作る前に確かめる」だけで防げます。

使うときのコツ

  1. そのまま貼ってOK。 合わないところは、自分の言葉に直してください。
  2. 入れても100%は守られません。 Claude Code の公式ドキュメントにも、こうした決まりごとは強制ではないこと、そして具体的で短い指示ほど守られやすいことが書かれています。
  3. 同じ失敗が2回続いたら、仕組みで止める。 ルールの文を足すより、「出す前にこのチェックリストで点検する」のような仕組みを作ってもらうほうが効きます。ボクがつけているAIの失敗記録（57件）をふり返ると、再発が止まったのは、点検の仕組みを作ったときだけでした。
