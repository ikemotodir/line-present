# 全自動で動く設定 ― Claude Code への丸投げ指示書

あなた（Claude Code）への依頼です。私のパソコンの Claude Code を、**いちいち許可を聞かずに最後まで自動で進める**設定にしてください。そのかわり、事故が起きにくいように守りの設定も一緒に入れてください。私はプログラムが分かりません。途中で質問せず、最後まで進めてください。

## やってほしいこと
1. ユーザー用の設定ファイル `~/.claude/settings.json` を開く（Windows なら `%USERPROFILE%\.claude\settings.json`）。無ければ作る。書き込むときに許可の画面が出たら、私に「はい」を押すよう1行で伝える。
2. 変更前に、元のファイルを日付つきでコピーして残す（例: `settings.json.bak-20260928`）。
3. すでにある設定は消さずに、次を足す（JSON の形を壊さない）。
   - `permissions.defaultMode` を `"bypassPermissions"` にする（新しいフォルダでは、許可を聞かないモードで始まる。前に別のモードを選んだフォルダは、そのモードのまま）。
   - **毎回確認させる操作**（`permissions.ask`）：
     - `Bash(rm *)`（ファイルの削除）
     - `Bash(git push *)`（外への送信）
     - `Edit(~/.claude/settings.json)`（この設定そのものの書き換え）
     - Windows なら `PowerShell(Remove-Item *)`・`PowerShell(git push *)` も
   - **絶対にやらせない操作**（`permissions.deny`）：
     - `Bash(git push *--force*)`・`Bash(git reset --hard *)`・`Bash(sudo *)`
     - Windows なら `PowerShell(git push *--force*)`・`PowerShell(git reset --hard *)` も
     - パスワードや鍵のファイル：`Read(**/.env)`・`Read(**/.env.*)`・`Read(~/.ssh/**)`
   - 書き方は、必ず公式ドキュメント https://code.claude.com/docs/ja/permissions で確かめてから書く。確かめられなかった項目は入れずに「未確認」として報告する。
4. サンドボックス（コマンドが触れる範囲をOSで制限する機能）は、公式ドキュメント https://code.claude.com/docs/ja/sandboxing によると macOS・Linux・WSL2 だけで使える。
   - Mac なら有効にする。
   - Windows（WSL2 を使っていない）なら設定に入れず、「このパソコンでは使えない」と報告する（入れても効かないのに、守られていると思い込むのを防ぐため）。
5. 書き終わったら、ファイルを読み直して、JSON として正しいか・設定が入っているかを確かめる。
6. 最後に、次を専門用語なしで短く伝える。
   - 何を変えたか（3行以内）
   - 元に戻す方法（コピーを元に戻すだけ）
   - 私がアプリの画面で自分でやる所（下の「画面でやること」）

## 画面でやること（私が自分でやる。あなたは案内だけ）
1. 設定の「Claude Code」の中にある、権限をバイパスするモードを許可するスイッチをオンにする（公式ヘルプの英語表記は「Allow bypass permissions mode」）。これを入れないと、モードの選択肢に出てきません。
2. Code の画面のモード選択で「権限をバイパス」を選ぶ。
3. 設定の「プライバシー」で、会話をAIの改善に使うスイッチ（ボクの画面では「AIモデルの改善に協力する」）をオフにする。オフにすると、会話の保管期間が短くなり、学習に使われません。
4. 夜中など、パソコンを離れている間も動かしたいときは、設定の中の、パソコンをスリープさせない設定をオンにする（公式の英語表記は Desktop app → General の「Keep computer awake」）。アプリは開いたまま、ノートパソコンのふたは閉じない。

## 大事な注意（私に必ず伝えること）
- このモードは、聞かずにファイルの削除・コマンドの実行・ネットへの接続までします。公式ドキュメントも「損害を起こせない、コンテナや仮想マシンのような切り離された環境でだけ使うように」と注意しています。
- 読んだWebページの中に仕込まれた悪い指示にも、ほぼ無防備です。自分の設定ファイルも書き換えられます（だから上で確認させる操作に入れています）。
- 禁止リストも完全な壁ではありません。別の書き方のコマンドや、プログラム経由の読み書きはすり抜けることがあります。大事なデータはバックアップを取り、パスワードやAPIキーを作業フォルダに置かないでください。
- Windows では、コマンドが届く範囲をOSで制限する壁（サンドボックス）がありません。
- 心配なら、確認を減らしつつ安全チェックが残る「自動」モードが、公式のおすすめです。

① 丸投げで入る設定（Claude Code が自分でやる）

  • 許可を聞かずに進むモード（権限をバイパス）で、毎回始まるようにする
  • そのかわり、削除と外への送信は毎回確認。履歴の上書き・管理者権限・パスワードの読み取りは禁止
  • Macならサンドボックス（コマンドが触れる範囲の制限）も入れる。Windowsでは使えません
  • 変更前の設定はコピーして残す（いつでも元に戻せる）

② 自分で切り替える所（アプリの画面）

  • 設定の「Claude Code」：権限をバイパスするモードを許可するスイッチをオン（公式の英語表記は「Allow bypass permissions mode」）。これが無いと選べません
  • Code のモード：「自動」→「権限をバイパス」
  • 設定 →「プライバシー」：「AIモデルの改善に協力する」をオフ（会話が学習に使われません）
  • 夜中も動かすなら：設定の中の、スリープさせない設定をオン（公式の英語表記は Desktop app → General の「Keep computer awake」）

リスクと守り方

  • 「権限をバイパス」は、聞かずに削除・実行・ネット接続までします。公式も「壊れても困らない、切り離した環境で使って」と注意しています
  • だから ①作業用のフォルダを分ける ②大事なデータはバックアップ ③パスワードやAPIキーをフォルダに置かない ④公開・送信・お金は、特典1のルール3で必ず確認させる
  • 禁止リストも完全な壁ではありません。不安なら、安全チェックが残る「自動」モードが公式のおすすめです
