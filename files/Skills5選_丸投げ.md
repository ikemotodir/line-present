# Skills5選 ― Claude Code への丸投げ指示書

あなた（Claude Code）への依頼です。下の5選のスキルを、私のパソコンの個人用スキルの場所に入れてください。私はプログラムが分かりません。途中で質問せず、最後まで進めてください。

## やってほしいこと
1. 個人用スキルの場所 `~/.claude/skills/` があるか調べる（Windows なら `%USERPROFILE%\.claude\skills\`）。**今あるか無いかを覚えておく**（6で使う）。無ければ作る（`.claude` フォルダ自体が無ければ、それも作る）。
   - ここに入れたスキルは、このパソコンのどのフォルダの作業でも使えます（公式ドキュメントのスキルのページ）。
   - 最初に書き込む前に、私に次を短く伝える。
     - 許可を聞かれたら、許可してほしいこと（`.claude` は、書き込むたびに確認が出ることがある場所のため。公式ドキュメントの権限モードのページ）
     - 選択肢に `Yes, and allow Claude to edit files in its ~/.claude folder for this session` があれば、それを選ぶと、この会話の間は聞かれる回数が減ること（画面は版で違うことがある）
2. 5選のスキルそれぞれに、`~/.claude/skills/<名前>/SKILL.md` を作る。<名前> は下の各見出しの英語の名前（例 `fact-check-before-send`）。
   - **同じ名前のフォルダがすでにあるときは、上書きしない。** 先にそのフォルダを `~/.claude/skills-backup/<名前>-<今日の日付>/` へ移して残してから、新しく作る（`skills` の中に残すと、同じ名前のスキルが2つになるため）。
   - 中身は、各スキルの `ここから` の行と `ここまで` の行の間を、一字一句そのまま書く（要約・短縮・言い換えをしない。区切りの線そのものは書かない）。文字コードは UTF-8。
3. 指示ノート（スキル2）を作業の前に読ませるため、ユーザー用のメモリファイル `~/.claude/CLAUDE.md`（Windows なら `%USERPROFILE%\.claude\CLAUDE.md`）の**一番下に**、次の2行（見出しと決まり）を足す。ここは、どのフォルダの作業でも、会話を始めるたびに読まれる場所です（公式ドキュメントのメモリのページ）。
   - 1行目（見出し）：`# 指示ノートを読む（Skills5選）`
   - 2行目（決まり）：`- 文・資料・ページ・アプリ・設定を作る前に、~/.claude/instruction-notebook.md（指示ノート）があれば読み、書いてある決まりを全部守る。`
   - 見出しを付けるのは、ほかの章（たとえば「絶対ルール」の章）を直す時に、この2行が巻き込まれないようにするため。
   - ファイルが無ければ作り、この2行だけを書く。
   - ファイルがあるときは、先に同じフォルダへ `CLAUDE.md.bak-skills` としてコピーを残す（同じ名前のコピーがすでにあれば、上書きせず、名前の後ろに今日の日付を付ける）。元の内容は消さない・変えない・並べ替えない。
   - 同じ見出しがすでにあれば、足さない（二重にしない）。
4. 書き終わったら、読み直して確かめる。
   - それぞれのフォルダに、SKILL.md が1つずつあること
   - 先頭が `---` の行で始まり、`name:` の値がフォルダの名前と同じこと
   - 中身が、この指示書の文と一字一句同じこと
   - `CLAUDE.md` の一番下に3の二行が一組だけあり、元の内容が残っていること（コピーと比べる）
5. 違っていたら直して、もう一度4を確かめる。
6. 最後に、次を専門用語なしで短く伝える。
   - 入れた場所と、スキルの名前。別の場所へ移して残した物があれば、その場所
   - `CLAUDE.md` に指示ノートを読む決まりを足したこと（足さなかったなら、その理由）と、コピーを残した場所
   - 1で `skills` フォルダが無かった（今回作った）ときは：入力欄に `/reload-skills` と打って送ること。それでも出なければ、アプリを終了して開き直すこと（Mac は Cmd+Q）（公式ドキュメントのスキルのページにも、作業の途中で新しく作ったスキルの場所は /reload-skills で読み込むと書いてある）
   - 確かめ方：`この会話で今使えるスキルの一覧に、fact-check-before-send・instruction-notebook・resume-from-progress・recording-to-notes・handoff-spec-maker があるか、1つずつある／ないで教えて` と送り、どれも、あると返ればOK
   - 使い方の例（そのまま送れる文。スキルごとに）
     - うそ止め点検：`この文、出す前にうそ止め点検して`
     - 指示ノート：`これからは〇〇にして。指示ノートに書いて`／`指示ノートを見せて`（ノートは `.claude` の中に書くので、書く時に許可を聞かれることがある）
     - 続きから：大きな作業を頼むときは `進み具合を残しながら進めて`、止まった後は `続きから`
     - 録音→記録：`この文字起こしを、話し手を分けて打合せの記録にして`（使う前に、録音とAIに読ませる事の両方に相手の同意をもらう）
     - 丸投げ指示書メーカー：`〇〇するアプリが欲しい。丸投げ指示書を作って`
   - 外し方：要らなくなったスキルは、`〇〇のスキルを消して` と送れば消せる。3の二行も、`指示ノートを読む決まりを CLAUDE.md から消して` で消せる

この5選のスキルと3の二行は、私に聞かずに消したり書き換えたりしないでください。

# うそ止め点検（出す前の事実の点検）

AIは、見ていない数字や、やっていない事を、それらしく書いてしまうことがあります。人に見せる文は、出す前にこの手順で点検します。

## 点検する物
- 数字（金額・人数・件数・割合・文字数など）
- 日付・曜日・期間
- 人・会社・商品・サービスの名前
- かぎかっこで囲んだ言葉（人の言葉・画面の文字・資料の文）
- URL
- やった事（作った・直した・確かめた・動いた・送った）

## 元になる物・ならない物
- 元になる：ユーザーがこの会話で書いた言葉／この会話で開いて読んだファイル（自分が書いたファイルは除く）／この会話で読んだWebページ／この会話で実際に動かしたコマンドの結果
- 元にならない：自分が前に書いた文（この会話でも、前の会話でも）／自分が作ったファイル・メモ・まとめ／覚えている知識や、たぶんこうだろうという考え／他のAIの答え

## 手順
1. 出す文を、まず下書きにする（まだ相手に見せない）。
2. 下書きから、上の一覧に当たる物を全部書き出す。
3. それぞれの元を探し、元の場所（ファイル名・URL・ユーザーの言葉）と、元の文を一字一句、横に書く。
4. 数字は、けたと単位まで同じか確かめる。計算した数は、元の数と式を書き、もう一度計算し直す。
5. かぎかっこの中は、元と一字一句同じか確かめる。自分の言い回しをかぎかっこで囲まない。
6. URLは、この会話で実際に開けた物だけ残す。
7. やった事は、この会話に記録（コマンドの結果・保存したファイル）がある物だけ残す。試していない物は（未試験）と書く。
8. 元が見つからない物は、消すか、後ろに（未確認）と書く。推測した物は［推測］を付ける。それらしい数字や名前で埋めない。
9. 直した下書きを、2からもう一度見る。直すときに新しく書いた数字や言葉も点検する。
10. 全部に元があるか、（未確認）か［推測］が付いてから出す。最後に、点検した物の数と、（未確認）の数を短く伝える。

## 守ること
- 言い切りすぎない（結果を約束する言葉を使わない）。
- 元が無いのに、元があるように書かない（URLや資料の名前を作らない）。

# 指示ノート（一度言われた事を、二度言わせない）

ユーザーが一度伝えた決まりを、会話が変わっても守るためのノートです。ノートは `~/.claude/instruction-notebook.md`（Windows なら `%USERPROFILE%\.claude\instruction-notebook.md`）だけ。無ければ作ります。

## 書き足す時
ユーザーが次のような事を言った時です。
- これからの決まり（今後は〇〇で／毎回〇〇して）
- やめてほしい事（〇〇はやめて／〇〇は使わないで）
- ボツにした案（その案はなし／却下）と、その理由
- 前にも言ったけど、と言われた事

## 書き方
1. ノートの一番下に、決まりごとに次の形で書き足す。
   `- 日付（YYYY-MM-DD）｜種類（決まり・やめて・ボツ）｜対象（全部、または作業やフォルダの名前）｜内容｜元の言葉（ユーザーの文を一字一句）`
2. ボツの案は、理由も書く。理由を言われていなければ（理由は未確認）と書く。
3. 前の行と食い違う時は、前の行を消さずに、新しい行に（〇〇の日付の行を変更）と書く。新しい方を守る。
4. 書いたら、何を書いたかを短くユーザーに伝える。
5. パスワード・鍵・カードの番号・他の人の個人情報は書かない。

## 作る前に読む
文・資料・ページ・アプリ・設定などを作る前に、次をする。
1. ノートを全部読む。
2. 対象が全部の行と、今の作業に当てはまる行を、全部反映する（並び順・言い回し・入れる物・入れない物）。
3. ボツの案は、理由を書かずにまた出さない。もう一度出すなら、前のボツの理由と、今回それが変わった点を一緒に書く。
4. 作り終わったら、反映した行を短く伝える。

## ノートを見る・直す
- 指示ノートを見せて、と言われたら、中身をそのまま見せる。
- 行を消して、と言われたら、消す前に、消す行を見せて確かめる。

# 続きから（止まっても、残りだけやる）

大きな作業は、使用量の制限・パソコンの停止・アプリの終了で、途中で止まることがあります。最初からやり直すと、時間も使用量も二重にかかります。だから進み具合をファイルに残しながら進めます。

## 始める時
1. 作業のフォルダに `進み具合.md` を作る。すでに別の作業の `進み具合.md` があるときは、`進み具合_作業の名前.md` にする。
2. 次を書く。
   - 目的（何ができたら終わりか）
   - 手順の一覧（手順ごとに、未・済の印をつける）
   - 作った物の場所（ファイル名）
   - つまずいた所と、どう直したか
   - 次にやる事
3. 途中で作った物（調べた結果・下書き・作ったファイル）は、その都度ファイルに保存する。会話の中だけに置かない。

## 進めている間
1. 手順が終わるたびに、`進み具合.md` の印を済にし、作った物の場所と次にやる事を書き直す。
2. 長くかかる手順は、さらに小さく分けて、分けた単位ごとに書き足す。
3. 全部終わったら、一番上に完了と書く。

## 続きから、と言われた時
1. 作業のフォルダの `進み具合.md` を読む（いくつかあれば、どれの続きかを一覧で見せて選んでもらう）。
2. 済になっている手順の、作った物が本当にあるかを確かめる。無い物だけを、未に戻す。
3. 未の手順だけを、上から順にやる。済の手順はやり直さない。
4. 始める前に、どこから再開するかを短く伝える。

# 録音→記録（話し手を取り違えない記録）

録音を文字にした物は、話し手が書かれていなかったり、途中で入れ替わったりします。思い込みで話し手を決めると、自分の話を相手の事として書いてしまいます。この手順で、根拠のある事だけを記録にします。

## 始める前に（大事）
- 録音と、AI（Claude）に読ませる事の両方を、相手に伝えて同意をもらってから。同意があるか分からない時は、ユーザーに確かめてから始める。
- 会話を Claude のモデルの改善（学習）に使う設定がオフになっているかを、ユーザーに確かめてもらう（Claude の設定のプライバシーの所）。オンなら、オフにしてから始めるよう勧める。
- 記録は相手の大事な情報です。ネットに公開しない・人に送らない・共有の場所に置かない。パソコンの外に出す時は、その前にユーザーに確かめる。

## 手順
1. **名前を伏せる**：ユーザーに、伏せたい名前（相手の名前・会社名・お店の名前など）を聞く。中身を読む前に、そのパソコンに最初からある機能（Windows は PowerShell、Mac はターミナルの置き換えなど）で、名前を札（〔相手〕〔会社A〕など）に替えた写しを作る。電話番号・メールアドレス・住所も札にする。そのあとは写しだけを読む（読んだ文はAIに渡るため）。
   - 文字コードは UTF-8 のまま読み書きする（Windows の PowerShell では、読む時も書く時も文字コードを指定する）。写しを作ったら、最初の数行だけ開いて、文字化けが無いか確かめる。化けていたら作り直す。
   - 住所など、置き換えられたか分からない物は、ユーザーに伝えて、伏せ方を相談する。
2. **話し手を決める**：前の流れ（さっきまで話していた人）だけで決めない。決め手にするのは、次の手がかりだけ。
   - 直前の質問への答えか。直後に相手が何と返したか
   - 誰の道具・事業・家族の話か（ユーザー自身の仕事や道具の話は、ユーザーの話）
   - 相づち・驚きの声・聞き返しの直後は、話し手が替わっていることがある（これだけで決めない）
   - 会議アプリの書き起こしに話し手の欄がある時は使う。ただし中身と食い違う所は、上の手がかりで決め直す
3. 手がかりが無い文は、記録に入れない。会議アプリの自動のまとめにしか無い事も入れない（まとめは誤りが混ざるため）。
4. 写しと同じフォルダに、記録ファイル `打合せ記録_日付.md` を作る。中身は次の順。
   - 相手の事（事業・困っている事・やりたい事・決まった事）
   - ユーザーが話した事（相手の事と分けて書く）
   - 次にやる事（誰が・いつまでに）
5. 同じフォルダに、根拠のファイル `打合せ記録_日付_根拠.md` を作る。記録の行ごとに、時刻・本人の言葉（文字起こしのまま）・誰の事か（相手／ユーザー）・話し手をそう決めた理由を書く。
6. **点検する**：次の行は、直すか消す。
   - 根拠の無い行
   - 文字起こしに無い言葉を、本人の言葉として書いた行
   - 相づちの直後の言葉を、前と同じ人の言葉にした行
   - ユーザー自身の事（出身・仕事・家族など）が、相手の事に入った行
   - 迷う行は（話し手未確定）と書き、相手の事には入れない
7. 最後に、記録の場所と、（話し手未確定）の数をユーザーに伝える。

配布：池本 将（合同会社スタジオパッチ）の公式LINE特典。自分で使うのは自由です。配り直しと販売はお断りします

# 丸投げ指示書メーカー

プログラムが分からない人でも、指示書を Claude Code に貼るだけで、アプリを作って試すところまで任せられるようにする手順です。

## 1. 欲しい物を聞く
- 足りない事があれば、最初にまとめて聞く（何をする道具か／誰が・Windows と Mac のどちらで使うか／何を入れて、何が出てくるか）。
- 答えが無い所は、良いと思う方で決め、指示書に（仮）と書く。

## 2. 指示書を書く
作業のフォルダに `アプリの名前_丸投げ.md` を作り、次の順で書く。

1. **題名**：`# アプリの名前 ― Claude Code への丸投げ指示書`
2. **あなた（Claude Code）へ**：次の文を入れる。
   - 私はプログラムが分かりません。この手順どおりに作り、自分で試してから渡してください。
   - 途中で私に質問しないでください。迷ったら良いと思う方を選び、最後に理由を1行で書いてください。
   - 管理者のパスワードが要る方法は使わないでください（私が入力する手間になるため）。
3. **まず、このパソコンを調べて準備する**：Windows か Mac かを調べる。何も入っていないまっさらなパソコンでも動く前提で、要る部品は公式の方法で、作業フォルダの中に入れる（パソコン全体を汚さない）。入れた直後にコマンドが見つからない時は、フルパスで呼ぶ。
4. **作るもの（これで完成）**：画面・入れる物・出てくる物・保存先・ファイル名の形。数字（上限・大きさ・時間）は先に決めて書く（作る人によって変わらないように）。データをパソコンの外に送らない作りにする（送る必要がある時は、何をどこへ送るかを書く）。
5. **つまずき対策**：分かっている落とし穴と、その時の直し方。
6. **合格の条件（満たすまで完成と言わない）**：見た目ではなく、機械で数えて判定できる条件にする。試すための材料（短い音声・練習用のページなど）は、Claude Code に自分で作らせる。
7. **起動と終了**：アプリなら、ダブルクリックで始められる形にし、黒い窓を出さない。拡張機能などは、入れ方を1手ずつ書く。
8. **途中で止まっても続きから**：終わった手順・残りの手順・つまずいた所を `進み具合.md` に書きながら進める。続きから、と言われたら、止まった所から再開する。
9. **最後に私へ伝えること（専門用語なしで短く）**：使い方（クリックする順に三行以内）／合格の条件ごとの結果（合格・不合格・未確認）／うまくいかない時に伝えればいい事（どの画面で・何をしたら・どうなったか）。
   - Windows か Mac の片方でしか試していなければ、もう片方は未確認と書く。試していない事を、できたと言わない。

1. まっさらなパソコンで、初めて読む Claude Code になったつもりで読み直す。どちらとも取れる所・決めていない数字・質問しないと進めない所を直す。
